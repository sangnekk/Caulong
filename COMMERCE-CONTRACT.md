# Commerce implementation contract

Laravel 13 answering Inertia page props; pages are React views in the Next.js app (frontend/); use existing dependencies, integer VND. UI Vietnamese, plain wording. No fabricated inventory/prices for real brands. Seed demo products explicitly is_demo=true (fictional names, existing generic poster) and label demo orders. Public / remains landing; /products is store. No payments/AI claimed live without configured provider.

## Catalog schema

brands/categories: id, name(120), slug unique(160), timestamps.
products: id, brand_id nullable FK nullOnDelete, category_id nullable FK nullOnDelete, name(160), slug unique(180), description text, image_path nullable string (relative public disk path or /models/hyper-core-poster.png), specs JSON nullable, play_style(attack|speed|balanced), skill_level(beginner|intermediate|advanced|all), is_active boolean default false, is_featured boolean false, is_demo boolean false, timestamps.
product_variants: id, product_id FK restrictOnDelete, sku unique(80), name(120), price unsignedBigInteger VND, compare_at_price nullable unsignedBigInteger (list price; shown only when above price), stock unsignedInteger, is_active boolean true, timestamps.
product_images: id, product_id FK cascadeOnDelete, path (public disk), hash char(64) sha256 of the file, position, timestamps. Further photos only; the main photo stays products.image_path. At most 12 per product.
Product relations brand/category/variants. Price/stock stored ONLY variants. Product image_url accessor: safe local Storage public URL, static poster fallback. Specs fields weight, balance, stiffness, material, max_tension strings (not unverified medical claims). Product catalog scopes active and variants active. Order item restrict deletion purchased variant; deactivate instead.

POST /cart/coupon cart.coupon.store {code<=40} (throttle 10/min) keeps the code with the cart (session key cart_coupon) when it applies right now, else error under "coupon" in the customer's words; DELETE /cart/coupon cart.coupon.destroy removes it. ## Orders schema

orders: id, public_id unique UUID, checkout_token unique UUID, user_id nullable FK nullOnDelete, name,phone,address,email nullable,notes nullable,status string default pending,payment_method string cod,payment_status string unpaid,subtotal/shipping_fee/total unsignedBigInteger,is_demo boolean false, timestamps.
order_items: id,order_id cascade,variant_id nullable FK restrictOnDelete,product_name,variant_name,sku,unit_price unsignedBigInteger,quantity unsignedInteger,line_total unsignedBigInteger,timestamps.
Order relationships items,user. No payment provider secrets or fake callback. COD marked paid only via explicit admin confirmation money collected, not merely delivered.
OrderService admin transitions uses transaction/lock: pending->confirmed|cancelled; confirmed->shipped|cancelled; shipped->delivered; delivered terminal. Cancel restocks exactly once, sorted variant lock; do not restore orders already cancelled. Admin calls OrderService.transition(Order,string) and markCodPaid(Order); worker implement.

## Email

users.marketing_opt_in_at nullable timestamp: when the customer agreed to promotional email; null = not agreed or taken back. Never ticked for them.
email_logs: id, type(40), recipient(190), subject, status queued|sent|failed (default queued), provider_message_id nullable, error nullable text, user_id nullable FK cascadeOnDelete, order_id nullable FK nullOnDelete, sent_at nullable, timestamps. Rows older than 365 days are pruned daily; nothing that must outlive a year relies on them (an offer is remembered by its coupon).
Every email goes through EmailService::send(type, recipient, ShopMail, user?, order?): log row first, then the App\Jobs\SendEmail job (3 tries, 60 s then 600 s apart; failed with the reason after the last). Nothing is sent inside a request, and a failure never fails the order or the sign-up. Laravel's verify-address and reset-password notifications are queued with the same tries and logged once sent.
Types: transactional welcome|order_placed|order_shipped|order_delivered|order_cancelled|coupon go to any usable address; marketing abandoned_cart|winback|post_purchase|vip only to a non-admin customer with marketing_opt_in_at set and a verified address, checked when queued and again when the worker sends (a customer who stopped in between gets nothing; the row ends failed with that reason). No email for a demo order or to an address at khach-mau.invalid. Marketing emails carry the unsubscribe link in the body and in List-Unsubscribe; transactional ones never do.
A customer's coupon is emailed as marketing (type = its campaign) when coupons.campaign is winback or vip, whoever sends it; any other personal coupon is a transactional gift (type coupon).
Order emails are sent once per step, by the call that moved the order: placed at checkout (not on a replayed token), then shipped, delivered, cancelled. Confirming sends nothing.
MarketingAutomation (php artisan marketing:run {automation?}; scheduled in routes/console.php in config shop.timezone, after crm:segment): each automation is off until its marketing_<name> setting is on; real orders and non-demo customers only; at most config shop.marketing.batch (200) emails per automation per run. abandoned_cart: last add_to_cart at least marketing_abandoned_cart_hours ago (1..72) and within 7 days, no order since, at most one per customer per 7 days. winback: segment inactive with a real order, own coupon (percent, max_discount 300000, single use), at most one per 180 days. post_purchase: marketing_post_purchase_days after delivered_at (up to 14 days late), once per order. vip: segment vip, own coupon, once per customer for good. An offer already made is known by its coupon (campaign + user_id), so a failed or dropped email never makes a second coupon.
MAIL_MAILER=resend: App\Mail\ResendTransport posts to https://api.resend.com/emails with Laravel's HTTP client (no SDK), key from RESEND_API_KEY only, 15 s timeout; Resend's id is kept in email_logs.provider_message_id. Tests fake the HTTP call; no real delivery is claimed.

## Admin endpoints/props

Admin routes prefix /admin with auth, verified, EnsureAdmin using user.is_admin boolean false. Public signup cannot assign is_admin (NOT fillable). Safe command shop:make-admin email promotes EXISTING verified account, no default secret/password; confirm prompt optional --force. No public admin elevation.
GET /admin -> admin/dashboard counts stats + latest orders (worker choose props UI matches).
GET /admin/products -> admin/products {products pagination all,brands,categories}; GET /admin/products/create and /admin/products/{product}/edit -> admin/product-form {product|null,brands,categories}.
POST /admin/products, PUT/PATCH /admin/products/{product}; multipart upload JPEG/PNG/WebP<=5MB validated, no SVG, image stored generated filename; file replacement safe after DB commit (or retain old files until cleanup if simpler). Product fields from schema, variants array id nullable/sku/name/price/stock/is_active. Never update stock while checkout without row lock; validate unique variants/sku + ownership; omissions do NOT delete existing variants. No hard delete needed; deactivate.
POST /admin/brands {name,slug}, POST /admin/categories {name,slug} from forms on product list. Name/slug validation unique.
GET /admin/customers/{user} admin.customers.show ?tab=overview|orders|timeline|products|reviews (&before=ISO time&skip=n to continue the timeline) -> admin/customer {customer:{id,name,email,verified,is_admin,joined}, overview:{orders,open,cancelled,ordered,spent,average,first_order_at,last_order_at}, tab, demo, recentOrders|null, orders (pagination)|null, timeline:{entries:[{type,at,key,product?,order?,data?}],next:{before,skip}|null}|null, products|null, reviews|null}: only the tab asked for is loaded. Demo orders count only where DemoData::shownByDefault().
Checkout and coupons: GET /checkout stores the discount it shows (session checkout_discount). POST /checkout quotes the coupon again inside the order transaction with the coupon row locked and the order's phone (per-customer limit: by account, and by phone for guests); a figure different from the one shown is refused (error "cart"), a coupon that was shown as applied and no longer is gives its reason (error "coupon"). The order saves discount_total and coupon_code and one coupon_redemptions row (order_id unique); a replayed checkout token returns the same order and adds none; cancelling the order deletes the row.
Customer groups: users.segment is one of new|potential|active|vip|inactive|lost (null for admins), set only by CustomerSegmentation (rules in its class comment, thresholds from ShopSettings::segments()). Hidden from the serialized user: never in auth.user.
GET /admin/customers accepts ?segment= and returns customers.data[].segment and segments:{group: count}. GET /admin/customers/{user} returns customer.segment (refreshed) and, for tab=coupons, coupons:{personal:[...],used:[{id,code,amount,at,order:{id,total}}]}.
GET /admin/coupons admin.coupons.index ?state=active|scheduled|ended|off&q= -> admin/coupons {coupons (pagination: terms, customer|null, segment, used, discounted, state: active|scheduled|expired|used_up|off), filters, counts}. GET /admin/coupons/create (?customer=id prefill) and /admin/coupons/{coupon}/edit -> admin/coupon-form {coupon|null (with starts_on/expires_on as shop days, products:[{id,name}], category_ids, used), customer|null, suggestedCode|null, categories, segments}. POST /admin/coupons, PUT /admin/coupons/{coupon}: code (normalised to upper case, unique, [A-Z0-9_-]), name, type, value (1-100 for percent), min_order, max_discount (percent only), starts_on/expires_on (Y-m-d, whole days in config shop.timezone), usage_limit, per_customer_limit, audience all|customer (customer_email of a non-admin account)|segment, campaign, category_ids[], product_ids[], is_active. DELETE /admin/coupons/{coupon}: refused once an order used it. GET /admin/coupons/products?q= (JSON) -> [{id,name}] real products by name or SKU for the form. POST /admin/coupons/{coupon}/email admin.coupons.email (throttle 10/min): queues the coupon's email to its customer; only a switched-on coupon made for one customer, else error "coupon". An automation's coupon is refused (error "coupon") while its customer has promotional email off.
GET /admin/emails admin.emails.index ?status=queued|sent|failed&type=(EmailService::TYPES)&q=(recipient) -> admin/emails {emails (pagination: id,type,recipient,subject,status,provider_message_id,error,user_id,order_id,sent_at,created_at), filters, types, counts:{all,queued,sent,failed}, mailer (config mail.default), stalled (queued for more than 10 minutes)}.
PUT /admin/settings also takes segment_vip_spend, segment_inactive_days, segment_lost_days (> inactive), segment_new_days, segment_potential_events; a request without them leaves them unchanged; changing them regroups every customer after the response. It takes the automations' switches and numbers the same way: marketing_abandoned_cart, marketing_winback, marketing_post_purchase, marketing_vip (boolean), marketing_abandoned_cart_hours (1..72), marketing_winback_percent and marketing_vip_percent (1..50), marketing_winback_valid_days and marketing_vip_valid_days (1..90), marketing_post_purchase_days (1..60).
GET /admin/reviews admin.reviews.index ?status=pending|published|hidden -> admin/reviews {reviews (pagination, each with product and customer), status, counts}; PATCH /admin/reviews/{review} {status: published|hidden}.
GET /admin/orders -> admin/orders; GET /admin/orders/{order} -> admin/order; PATCH /admin/orders/{order} {status}; POST /admin/orders/{order}/collected mark COD received through OrderService; auth+CSRF. State allowlist server and UI.
